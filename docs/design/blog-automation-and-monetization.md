> 작성일: 2026-07-27
> 상태: 설계 완료, 검토 대상

---

## 1. 목적

1. **기술 시리즈 자동 발행**: PonsLink/PonsWarp 커밋 기반 글을 하루 15건까지 자동으로 Tistory에 발행
2. **수익화**: 애드센스 기반 광고 수익 창출을 위한 고검색량/고CPC 키워드 글 병행 발행
3. **이미지 자동 생성**: Codex Imagen으로 대표 이미지, PIL로 기술 다이어그램 자동 생성
4. **카테고리 확장**: 기존 2개(개발지식, 개발 회고)에서 5개로 확장

## 4. 콘텐츠 유형과 파이프라인

### 4.1 유형 A: 기술 시리즈

```
소스: GitHub 커밋 로그 / 코드 분석
원고: .txt → tistory-blog 스킬로 HTML 변환
이미지: PIL 다이어그램 (다크 테마)
카테고리: 개발지식 / 개발 회고
시간대: 14:00, 22:00 (개발자 타겟)
```

**글쓰기 흐름:**
1. 커밋 메시지에서 주제 추출
2. 해당 코드 파일 읽기
3. tistory-blog 스킬 규칙으로 원고 작성
4. PIL로 다이어그램 1~2장 생성
5. HTML 템플릿 적용 (max-width 800px)
6. `queue-add.mjs`로 큐 등록

### 4.2 유형 B: 수익화 정보글 (고CPC)

```
소스: 키워드 리서치 → 검색량/CPC 데이터
원고: AI가 키워드 기반으로 작성
이미지: Codex Imagen으로 대표 이미지 1장
카테고리: 투자·재테크 / 생활·정보
시간대: 07:00, 09:00, 17:00 (검색 피크)
```

**글쓰기 흐름:**
1. 키워드 선정 (검색량 1만+ / CPC 500원+)
2. 네이버/Google에서 상위 10개 글 분석
3. 기존 글보다 더 깊거나 다른 관점으로 작성
4. Codex Imagen으로 대표 이미지 생성
5. HTML 템플릿 적용
6. SEO 메타: title, description, tags 최적화
7. `queue-add.mjs`로 큐 등록

### 4.3 유형 C: 비교/리뷰글

```
소스: 제품/서비스 조사
원고: 비교표 + 장단점 분석
이미지: Codex Imagen + HTML 테이블
카테고리: IT·테크 / 생활·정보
시간대: 12:00, 20:00
```

**투자/재테크 글 대표 이미지:**
```
Professional financial chart illustration, clean white background,
blue (#3b82f6) and green (#10b981) accent colors, upward trending
graph elements, modern flat design, 1280x720, blog thumbnail
```

**생활 정보 글 대표 이미지:**
```
Warm friendly lifestyle illustration, soft pastel colors,
clean modern design, relevant iconography, 1280x720, blog thumbnail
```

**IT 도구 비교 글 대표 이미지:**
```
Tech comparison illustration, split-screen layout, dark theme,
app icons or tool logos, vs symbol in center, 1280x720, blog thumbnail
```

### 6.2 구현: 시간대별 cron

현재 `publish-queue.timer`는 08:55에 하루 전체를 한 번에 제출한다.
시간대 분산을 위해 **7개 timer**로 확장:

```ini
# deploy/publish-queue-0700.timer
[Timer]
OnCalendar=*-*-* 07:00:00
Persistent=true

# deploy/publish-queue-0900.timer
[Timer]
OnCalendar=*-*-* 09:00:00
Persistent=true

# ... (07:00, 09:00, 12:00, 14:00, 17:00, 20:00, 22:00)
```

각 timer는 해당 시간대의 큐 파일만 제출:

```bash
# publish-queue.sh에 시간대 파라미터 추가
node scripts/schedule/submit-queue.mjs \
  --queue-dir /srv/publish-workbench/scheduled/queue \
  --date $(date +%Y-%m-%d) \
  --time-slot 0700
```

### 6.3 큐 파일 구조 변경

기존: 날짜별 1파일 → **날짜+시간대별 파일**:

```
scheduled/queue/
├── 2026-07-28-0700.json    (2건)
├── 2026-07-28-0900.json    (3건)
├── 2026-07-28-1200.json    (2건)
├── 2026-07-28-1400.json    (2건)
├── 2026-07-28-1700.json    (3건)
├── 2026-07-28-2000.json    (2건)
└── 2026-07-28-2200.json    (1건)
```

`queue-add.mjs`에 `--time-slot` 옵션 추가:

```bash
node scripts/schedule/queue-add.mjs \
  --date 2026-07-28 --time-slot 0700 \
  --title "ISA 추천 2026: 초보자가 꼭 알아야 할 5가지" \
  --body-file content/isa-guide-2026.html \
  --category "투자·재테크" \
  --tags "ISA,투자,절세,2026"
```

## 8. 콘텐츠 생성 자동화

### 8.1 자동화 흐름

```
[1단계: 키워드 큐]
  keywords.json — 선정된 키워드 목록
  각 키워드에 meta: { keyword, category, cpcTier, searchVolume, contentType }

[2단계: 글 생성]
  AI가 키워드별로:
  1. 네이버/Google 상위 글 분석 (source-import.mjs 활용)
  2. tistory-blog 스킬 규칙으로 원고 작성
  3. 대표 이미지 생성 (Codex Imagen)
  4. HTML 포맷팅
  5. meta 태그 설정 (title, description, tags)

[3단계: 큐 등록]
  queue-add.mjs로 시간대별 큐에 등록
  하루 15건, 7개 시간대로 분산

[4단계: 자동 발행]
  ponslink 서버 cron → agbrowse → Tistory
```

### 8.2 글 생성 스크립트 (신규 필요)

## 13. 설계 검토 (Design Review)

### 13.1 발견된 설계 결함

#### 결함 1: 시간대별 cron은 과도한 복잡도

**문제**: 7개 systemd timer를 관리하는 건 오버엔지니어링이다.
기존 `publish-queue.timer` 하나로 충분하다.

**근거**: `queue-add.mjs`가 이미 `publishAt` 필드를 지원한다.
Worker가 큐를 읽을 때 `publishAt` 기준으로 필터링하면,
하나의 timer로도 시간대별 발행이 가능하다.

**수정**: timer 7개 대신, `submit-queue.mjs`에 `--time-slot` 필터만 추가.
기존 타이머는 그대로 유지.

#### 결함 2: 콘텐츠 생성 파이프라인이 실제 존재하지 않음

**문제**: 설계 문서는 "AI가 글을 쓴다"고 설명하지만,
키워드 → 원고 → HTML → 이미지까지 처리하는 실제 스크립트가 없다.

**위험도**: 높음. 이 없이는 자동화가 동작하지 않는다.

**해결**: `scripts/content/generate-post.mjs`를 반드시 구현해야 한다.
최소한:
1. 키워드를 받는다
2. 네이버/Google에서 상위 글을 수집한다 (source-import.mjs 활용)
3. tistory-blog 스킬 규칙으로 원고를 작성한다
4. Codex Imagen으로 대표 이미지를 생성한다
5. HTML 파일로 저장한다

#### 결함 3: 애드센스 부트스트랩 전략 누락

**문제**: 바로 하루 15건씩 발행하면 애드센스 거부 확률이 높다.

**근거**: 애드센스 승인 조건:
- 원본 콘텐츠 30개 이상
- 일정 수준의 트래픽
- 정책 준수 콘텐츠

**수정**: 2단계로 나눠야 한다:
1. **부트스트랩기 (2주)**: 일 3~5건, 품질 우선, 기술 글 중심
2. **스케일업기 (3주차~)**: 애드센스 승인 후, 일 10~15건으로 확대

#### 결함 4: 이미지 업로드 경로 불명확

**문제**: Codex Imagen으로 생성한 이미지를
어떻게 Tistory 글에 삽입하는지 흐름이 빠져있다.

**현황**: 현재 agbrowse-automation은 `<img src="...">`를
Tistory 에디터에 넣는다. 하지만 외부 URL 이미지는
Tistory가 자체 호스팅으로 복사한다.

**해결**: 두 가지 경로:
1. **외부 URL**: 생성된 이미지를 temporary URL로 노출 → Tistory가 자동으로 가져감
2. **로컬 파일**: PIL/Imagen 결과를 서버에 저장하고 Tistory 이미지 업로드 API 사용

**권장**: 당장은 PIL 다이어그램을 base64 data URL로 인라인 embedding.
Codex Imagen은 나중에 연동.

#### 결함 5: 키워드 검색량 데이터 근거 없음

**문제**: "월 검색량 5만+" 등 모든 수치가 추정이다.
실제 데이터 없이는 키워드 선정 기준이 무의미하다.

**해결**: 최소한 네이버 검색광고 키워드 도구에서 실제 검색량을 확인해야 한다.

#### 결함 6: Tistory 일일 발행 제한 미검증

**문제**: "하루 15건"이라는 제한이 실제로 존재하는지 확인 필요.
일부 사용자에 따르면 하루 10건 제한이라는 말도 있다.

**해결**: 실제 테스트가 필요하다.

### 13.2 설계 수정 권고사항

| # | 결함 | 심각도 | 수정 방향 |
|---|------|--------|----------|
| 1 | 시간대 cron 과잉 설계 | 중 | 기존 timer 유지 + submit-queue에 필터 추가 |
| 2 | 콘텐츠 생성 스크립트 누락 | **높음** | generate-post.mjs 반드시 구현 |
| 3 | 애드센스 부트스트랩 없음 | **높음** | 2단계 전략 도입 |
| 4 | 이미지 업로드 경로 불명 | 중 | base64 인라인 → 이후 이미지 API |
| 5 | 키워드 데이터 추정 | 중 | 네이버 키워드 도구로 검증 |
| 6 | 발행 제한 미검증 | **높음** | 실제 발행 테스트 필요 |

### 13.3 검토 결론

현재 설계는 **인프라 레이어(큐 → 발행)는 완비**되었으나,
**콘텐츠 레이어(키워드 → 글 → 이미지)가 사실상 비어 있다**.

가장 시급한 작업:
1. `generate-post.mjs` 구현 (키워드 → HTML 글 자동 생성)
2. 키워드 실제 검색량 데이터 수집
3. Tistory 일일 발행 제한 실측
4. 애드센스 부트스트랩 계획 수립
