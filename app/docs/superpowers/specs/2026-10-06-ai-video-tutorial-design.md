# AI 영상 제작 튜토리얼 자동 발행 설계

작성: 2026-10-06. 요청: 다국어 웹 제작법 수집 → 한국어 가공 → 실제 프롬프트/결과 검증 → 게시·발행. 영상 생성은 제외하고 제작 시트와 씬별 Flow 프롬프트를 제공한다. 사용자가 설계 문서 기록 후 적용까지 명시적으로 요청했다.

## 1. 결정과 대안

별도 `ai-video` producer를 추가하되 기존 `submit-queue`/Job API/브라우저 워커를 재사용한다. 범용 generate-post 프롬프트에 모든 요구를 추가하는 대안은 실제 제작 증거를 보장하지 못한다. 별도 발행 서비스 대안은 중복·로그인·워커를 이중 관리하므로 채택하지 않는다.

초기 운영은 일 1건, Asia/Seoul 날짜 기준 18:30 생성 타이머, 검증 완료 뒤 최소 15분 후 미래 시각 큐 등록이다. 기존 두 트랙의 30건 정책은 변경하지 않는다. 추가 글은 AI·P2P 카테고리 안에서 별도 `contentTrack=ai-video`와 태그 `AI영상제작`으로 식별한다. 주제는 병맛 드라마, 두 고양이 버디 코미디(기존 영화/캐릭터 복제 아님), 숏드라마, 가상 브랜드 AI 광고, 스토리보드 시트, 캐릭터 시트, 프롬프트 변형 실험을 순환한다. 반복 배치로 일 상한을 넘기지 않으며 이미 큐/Job에 접수된 프로젝트를 다시 제작하지 않는다.

## 2. 현재 운영 접점

운영 루트 `/srv/publish-workbench/app`, 큐 `/srv/publish-workbench/scheduled/queue`, 결과 `/srv/publish-workbench/data`. 기획에는 `.env.local`의 MiMo v2.5 OpenAI-compatible 텍스트 API를 사용한다. 실제 이미지 생성은 OAuth smoke를 확인한 Codex Imagen helper `/home/declan/apps/codex-imagen/scripts/codex-imagen.mjs`를 사용한다. 시각 검수는 고정 설치한 `@openai/codex@0.160.1` CLI의 실제 이미지 입력과 기본 모델 `gpt-5.6-luna`를 사용한다. 비밀 값은 로그·문서·본문에 저장하지 않는다.

기존 submit-queue는 원장/RSS 중복 검사, 본문 QA, 이미지 inline, idempotencyKey와 notBefore를 가진 Job 제출, submitted/failed 이동을 담당한다. 새 생성물이 일반 생성기/auto-queue에 재수집되지 않도록 전용 산출물 디렉터리를 사용한다. 새 트랙의 주제·키워드는 자체 topics.json에서 관리하며 공유 keywords.json은 변경하지 않는다. 일반 생성기는 creative 엔트리를 제외한다.

## 3. 다국어 검색과 출처 계약

검색 언어 ko/en/ja/zh/es를 지원하고 주제별 현지어 검색어를 설정에서 관리한다. 검색 결과는 발견용이며 원문을 직접 취득해 본문을 추출한 제작법 자료만 근거로 쓴다. 검색 엔진 실패, WAF, 로그인, 빈 결과를 성공으로 가장하지 않고 수집 보고서에 기록한다. 공식 자료와 실제 제작 튜토리얼 URL을 seed로 제공하되 실행 때 다시 읽는다. 실제 본문에 사용한 제작법 출처가 서로 다른 문서 2개 이상, 언어 2개 이상, 사이트 2개 이상이어야 한다. 일반 AI 홈페이지, 사용하지 않은 자료, 동일 문서의 현지화만으로는 충족하지 못한다. agbrowse의 강한 추출 성공을 사용하고 약한 결과는 별도 안전 fetch·본문 검증을 통과해야 한다. 차단을 우회하거나 실패를 성공으로 표시하지 않는다.

출처 레코드: id/url/finalUrl/title/language/retrievedAt/contentSha256/text/sourceKind. 수집량·페이지 길이·timeout은 제한한다. 웹 내용은 비신뢰 데이터이며 실행 명령/시스템 지시로 사용하지 않는다. 공개 HTTP(S)만 허용하고 loopback/사설 주소/비HTTP 리다이렉트를 차단한다. 수집 원문은 프로젝트 references에 보존하고 게시물에는 한국어 요약·출처 링크를 넣는다.

원문의 방법/일반적인 프롬프트 구조를 학습하되 타인의 스토리·대사·캐릭터·결과 영상을 복제하지 않는다. 새 캐릭터·사건·프롬프트는 자체 제작으로 명시한다. 원문 전체 번역 재게시, 라이선스 미확인 결과물 복사, 실존인물/브랜드 허위 광고는 제외한다. 실제 사례가 없는 성능·수익·조회수 주장은 만들지 않는다.

## 4. 제작 패키지와 스킬 적용

프로젝트 루트 `/srv/publish-workbench/app/content/ai-video/<project-id>`를 사용한다. 스킬의 창작 규칙을 프로젝트용 어댑터로 적용한다. creative-production, orchestrating-video-preproduction, developing-video-synopses, designing-video-character-sheets, storyboarding-video, video-production-assets, codex-imagen, tistory-blog, video-prompt, video-model-router의 필요한 문서/실행 파일을 `/srv/publish-workbench/app/.codex/skills`에 배치하고 버전·해시를 기록한다. 실제 읽은 스킬 텍스트를 LLM 제작 브리프에 넣는다. 모델별 문장 구조는 dialects.json을 참고하되 기능·길이는 실행 때 읽은 공식 Flow 문서가 우선한다. 영상 가격은 미확인이므로 비용 추천·영상 실행은 하지 않는다. 스킬 복사만으로 에이전트가 자동 실행된다고 주장하지 않는다.

로컬 스킬은 recording-production-history 의존성이 설치되어 있지 않다. 전체 일반 studio 엔진의 설치로 가장하지 않는다. 이 트랙은 프로젝트별 project.json과 append-only .history로 정확한 요청/입력/출력/실패를 기록하는 명시적인 호스트 어댑터를 사용한다. 생성·렌더·검수·발행 기록을 유지하며 승인 이력을 발명하지 않는다.

제작 순서: 자료 정리 → 독창적인 짧은 시놉 → 캐릭터별 고정 앵커/행동/시트 프롬프트 → 실제 캐릭터 시트 → 캐릭터 시각 검수 통과 → 씬별 시작/끝 상태와 이미지 프롬프트 → 통과한 캐릭터 참조를 실제 입력한 clean keyframe 생성 → 외부 캡션을 가진 결정론적 스토리보드 시트 조립 → 실제 시트의 clean 패널 및 씬별 분리 → 프레임·합본 시각 검수 → 한국어 튜토리얼. 캐릭터 검수 실패·미확인은 씬 이미지 생성 전에 보류해 부적합한 참조에 추가 생성 비용을 쓰지 않는다.

범위는 짧은 1~3개 씬, 씬당 10초, 시작/끝 keyframe 2개이며 시트당 최대 8패널이다. 캐릭터 없는 광고/그래픽 예제에는 억지 캐릭터를 만들지 않는다. 캐릭터가 있는 예제는 캐릭터당 실제 identity sheet 1개에 전신 정면·3/4·측면·후면과 얼굴 정면·3/4·측면의 정확히 7뷰를 제공한다. 반복 identity/색/소품 점유를 씬과 참조에 연결한다. 샷은 scene/shot/beat/panel ID, 카메라·구도, 공간 배치, VFX(사용 또는 N/A 사유), 대사·립싱크(또는 무대사 사유), 음향 계획(실제 생성 아님), 시간/시작끝 상태를 포함한다.

## 5. 실제 테스트 증거와 발행 게이트

단순 파일 존재나 LLM의 자기평가는 통과가 아니다. 이미지 생성 시 prompt 원문 파일, SHA256, 모델/설정, 실제 참조 파일/hash, 호출 시각/종료 상태, 실제 결과 파일/hash/해상도를 기록한다. 재사용과 재시도를 구분하고 완료된 파일이 있으면 중복 생성하지 않는다. 임의 stock hero는 이 트랙의 결과를 대신할 수 없다.
Imagen helper의 JSON 계약은 `images[].path`를 사용한다. 여러 결과로 첫 파일이 재명명되면 `decodedPath`가 옛 경로로 남을 수 있으므로 임의 재귀 경로 수집은 하지 않는다. 실제 존재하는 완료·비부분 결과 중 마지막 파일을 선택하고, 보고된 각 출력 경로·해시·상태와 선택 여부를 기록한다. 부분 결과만 있거나 완료 파일이 없으면 생성 실패로 차단한다. 게시하지 않은 변형을 최종 결과로 표시하지 않는다.

Codex 이미지 입력으로 모든 실제 캐릭터/clean keyframe/조립 시트를 검수한다. 캐릭터 검수가 실패하거나 불확실하면 keyframe 생성 전에 멈춘다. 리뷰에는 입력 파일 hash, 프롬프트 hash, 관찰 내용, 캐릭터 앵커·패널 사건·연속성·가독성의 문제와 판정이 필요하다. 검수 프로세스 실패/빈 JSON/누락 검사/결과 부적합은 needs_review로 보류한다. 자동 의미 검수는 모델 검수이며 사람 승인으로 표기하지 않는다. 사람이 실제 이미지와 매칭을 확인한 파일별 관찰을 별도로 남길 수 있다.
시작·끝 이미지는 각각 한 순간의 정적 상태로 검수한다. 과거 동작이나 앞으로의 움직임, 정확한 초수·측정 불가능한 거리까지 한 정지 화면에서 증명하도록 요구하지 않는다. 합본에는 각 패널의 고유 시작/끝 상태를 이미지 밖 캡션으로 붙인다. 합본 검수에 원본 시트와 각 clean 패널 상세 이미지를 함께 입력하고 경로·해시를 리뷰 요청 해시에 포함한다. 실패 결과와 정확한 당시 프롬프트는 .history/attempts에 보존하며, 현재 결과 해시에 대응하는 실제 리뷰만 발행 판정에 사용한다.
합본의 캡션은 줄 수를 잘라 버리지 않고 전체 문장을 줄바꿈한다. 설정된 캡션 높이는 최솟값이며, 실제 폰트 행 높이와 가장 긴 캡션의 모든 줄에 맞춰 이미지 밖 밴드를 확장한다. 렌더 작업 키에 렌더러 파일 해시를 포함해 구현이 바뀌면 이전 합본을 다시 사용하지 않는다. clean 패널에는 캡션 픽셀을 포함하지 않는다.
시각 검수는 임시 독립 디렉터리에서 read-only, ephemeral, 사용자 설정·규칙 미적용으로 실행한다. shell/unified-exec/외부 앱·플러그인·다중 에이전트·웹 검색 도구를 비활성화하고, 도구 실행 이벤트가 있으면 판정을 거부한다. 실제 파일을 이미지로 첨부하고 JSON Schema로 최종 응답을 제한한다. 높은 추론 설정으로 실행하되 최종 JSON만 저장하며 사고 과정 원문은 출력·게시하지 않는다. 모델명과 추론 선택을 검수 요청 해시에 포함하여 이전 MiMo/다른 모델의 통과 캐시를 재사용하지 않는다. 기존 MiMo 시도의 실제 실패·불확실 판정은 보존한다. 자동 의미 검수는 결정론적 판정이나 사람 승인을 보장하지 않는다.


evidence gate는 발행 직전에도 project.json을 읽어 프롬프트/이미지/검수의 해시와 참조 버전을 재확인한다. 게시 HTML의 정확한 프롬프트 code 블록과 이미지가 기록된 실행 입력/결과와 일치해야 한다. 문장 가공용 LLM은 이 블록을 수정하지 못한다. 누락·변조·예전 결과 재활용·미검수 패널·미검증 원문은 큐 등록과 Job 제출을 차단한다. 이미 실패/보류한 자료를 일반 큐로 우회하지 않는다.

생성형 결과는 비결정적이므로 동일 픽셀 재생성 보장을 쓰지 않는다. 글은 '아래 실제 입력으로 얻은 이번 결과'만 주장한다. 영상은 실행하지 않으므로 어떤 문구에서도 영상 재현 성공/완성 영상이라고 주장하지 않는다.

## 7. 한국어 글과 게시

본문은 읽은 출처의 한국어 재작성(최소 1800자) + 독창적인 실습 설명 + 정확한 사용 프롬프트 + 실제 시트 이미지 + 씬별 Flow 프롬프트 + 실패/한계/재현 설정 + 출처다. tistory-blog/qa-post의 기존 서식과 금지 패턴/HTML 기준을 유지한다. 결과 블록과 설정·검수 사실은 결정론적 렌더러가 삽입한다. 외국어 프롬프트는 code/pre에 두며 설명은 한국어로 작성한다.

검증 통과 후 현재 시각보다 최소15분 미래의 +09:00 publishAt을 지정해 기존 파일 큐에 등록한다. 큐 read-modify-write의 공통 락과 원자 교체를 새 producer 및 기존 관련 writer에 적용해 생성/제출 충돌을 막는다. 일반 batch 생성기는 전용 creative 엔트리를 제외한다. 한 날짜의 ai-video 접수 이력을 queue/submitted/project 기록에서 확인해 일 1건 상한을 유지한다. 타이머는 network-online 이후 declan 사용자, 기존 env, bounded timeout을 사용한다. 실패는 로그/보류 상태로 남기며 영상 생성으로 fallback하지 않는다.

## 8. 검증·배포 수락 기준

- 5개 언어 검색 시도와 실제 원문 취득 보고, 실제 사용한 제작법 출처 최소 2개 언어·2개 문서·2개 사이트를 만족하는 예제.
- 캐릭터 시트/전 씬 시작끝 패널/실제 합본 및 clean 분리 파일, 모든 파일의 입력-출력 hash 연결.
- 누락/변조/판정 unknown/미지원 Flow duration이 발행을 막는 영구 회귀 테스트.
- 기존 본문 QA와 큐 제출 경로를 통과한 실제 게시물 한 건, 공개 URL HTTP200/제목/프롬프트/시트 이미지 확인.
- 자동 타이머 등록·활성 및 다음 실행 시각 확인.
- 기존 글/비밀/키워드 상태 보존. 코드 변경·스킬 버전·설계·검증 결과 기록.
- 영상 생성·영상 테스트를 하지 않았음을 글과 작업 보고에서 유지.

기존 분석에서 확인된 일반 워커의 불확실 성공 판정 등 광범위한 수리는 이번 범위에 포함하지 않는다. 첫 실습의 공개 페이지는 별도로 직접 확인한다.
