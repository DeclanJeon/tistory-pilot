# 시리즈·에피소드 운영 (온디맨드 심화)

모듈 02, 13, 14의 심화. 반복 캐릭터·회차 구조·러닝 개그·로어 진행·클리프행어·콜백·스폰서 슬롯이 있는 연작 콘텐츠 IP에 연다.

## 1. 시리즈 엔진 설계

일회성 영상 대신 반복 가능한 시스템을 만든다. 반복 출연만으로는 시리즈가 아니며 반복 가능한 갈등 엔진이 필요하다.

1. 시리즈 형식을 정한다: 스케치 코미디·로맨스 판타지·일상물·모큐멘터리·브랜디드 엔터테인먼트·고정 진행자 앤솔러지 등.
2. 관객 약속을 한 문장으로 쓴다. 예) "매회 현대 상식 문제 하나를 멜로드라마 로판 궁정 세계에 넣는다."
3. 시리즈 엔진을 정의한다: 반복 문제 원천·반복 모순/코믹 긴장·반복 세트·반복 관계 삼각/앙상블 역학·반복 시각/음향 모티프.
4. `assets/series-bible-template.md`로 시리즈 바이블을 만든다: 정체성·엔진·반복 캐스트·세계/톤 규칙·에피소드 템플릿·러닝 메모리·상태 델타.
5. 반복 캐릭터·관계마다 연속성 원장을 유지한다: 관객이 이미 아는 것·현재 관계 상태·미해결 오해·시그니처 개그/대사·의상/소품 앵커. `assets/continuity-ledger.csv`를 재사용한다.
6. 에피소드 템플릿: 콜드 오픈/훅 → 전제 트리거 → 에스컬레이션 비트 → 중반 반전/공개 → 감정·코믹 보상 → 클리프행어/콜백.
7. 콜백 층위: 같은 회차 콜백 · 이전 회차 콜백 · 시즌 러닝 개그/모티프.
8. 회차 요청마다 상태 델타를 기록한다: 영구 변화·새로 드러난 것·미해결 잔여·나중에 참조할 것·다음 회차 씨앗. 델타는 `project.json` 원장의 artifact/dependency 갱신과 issues로 남긴다.
9. 스폰서·광고가 있으면 [스폰서·제품 통합](19-brand-product-integration.md)의 통합 절차로 보낸다.

### 대사 많은 AI 연작의 제작량·연재 페이스 점검

월별 회차 목표나 제작 가능성을 판단해 달라는 요청, 특히 대사 비중이 큰 AI 시리즈에서는 생성에 들어가기 전에 작업량을 분해한다.

1. 제작자/팀의 실제 월 가용 시간, 목표 회차 수와 길이, 납품 범위를 확인한다. 입력되지 않은 인력·가용 시간을 가정하지 않는다.
2. 회차당 작업 단위를 기록한다: 각본·수정, 대사 라인/턴·화자·보이스 생성과 청취, 샷·고유 장소/에셋 수, 생성과 검토/재시도, 립싱크·오디오·자막·편집, 연속성 QA·내보내기·전달. 공통 시리즈 바이블·기준 에셋 준비는 회차별 반복 작업과 분리한다.
3. `assets/14-production-ops-template.md`의 반복 제작 작업량 표에 단위 수, 단위당 소요시간과 근거, 회차당 합계, 월 cadence 환산량, 종속 단계와 병목을 적는다. 각 작업 묶음에 기존 담당 스킬/참조 경로를 연결해 중복 절차를 만들지 않는다. 이력에서 측정한 값·사용자가 제공한 추정·미확인을 구분하고 수정/재시도 여유를 명시한다.
4. 월간 수요를 사용자가 제공한 실제 용량 및 확인 가능한 파이프라인 근거와 비교한다. 목표 러닝타임·대사 줄 수만으로 전체 작업시간이나 가능 여부를 단정하지 않는다. 대사·음성·립싱크·편집의 의존성은 [각본·대사](03-screenplay.md)와 [대사·립싱크](22-dialogue-lipsync.md), 샷별 도구 제약은 [AI 인계](11-ai-handoff.md), 최신 실행 한도·가격은 [생성 경로·비용](24-production-execution.md)에서 확인한다.
5. 결론은 제공된 근거에 따라 가능·조건부·미결정·현재 용량 초과 중 하나로 설명한다. 과거 측정치나 현재 확인된 용량이 없으면 미결정으로 두고 필요한 입력/측정만 제시한다. 모델 처리량·응답시간·재시도율·가격을 고정값으로 만들지 않는다.
6. 미달 시 회차 수·길이·대사/장소/고유 샷 수·승인된 에셋 재사용·납기 중 가능한 선택지를 트레이드오프로 제시한다. 사용자가 승인하기 전에 목표나 범위를 조용히 줄이지 않으며, text-only 계획 요청에서 실제 생성·업로드·편집은 시작하지 않는다.

## 2. 규칙

- 시리즈 상수(세계 규칙·관계 구조·약속)와 회차 변수(사건·단역·소품)를 분리한다.
- 이야기 연료를 만드는 인물 모순을 평탄화해 모두 유능하게 만들지 않는다.
- 콜백은 기억에 보상해야 하며 같은 대사 반복은 부족하다.
- 각 회는 단독으로 이해 가능하면서 장기 시청자에게 보상한다.
- 미해결 실타래는 의도적으로 추적한다. 로어를 우연히 만들지 않는다.
- 승인된 상태를 근거 기록 없이 덮어쓰지 않는다. 얼굴·제품·세계 규칙·비주얼 모드 변경은 해당 종속물을 stale로 표시한다(계약 참조).

## 3. 산출물

시리즈 로그라인·관객 약속, 엔진 요약, 반복 캐스트와 역할 기능, 세계/톤 규칙, 에피소드 템플릿, 러닝 개그·콜백 뱅크, 연속성 원장, 현재 회차 아이디어, 회차 후 상태 델타, 향후 회차 훅, 요청 시 근거·미확인을 구분한 회차 제작량·월 연재 페이스 판정.

## 관련 모듈

- 장기 상태(승인 SSOT·에피소드 델타·stale 추적)는 `project.json` 원장과 모듈 14의 운영 절차로 유지한다. 별도 상태 파일이나 두 번째 원장을 만들지 않는다.
- 신규 반복 캐릭터 도입 시 SSOT 티어 판정: [비주얼 모드·SSOT](20-visual-mode-ssot.md).
- AI 시리즈 제작량·월 연재 페이스는 `assets/14-production-ops-template.md`에 회차 작업 단위와 월 총량을 기록한다. 대사 타이밍은 `03-screenplay.md`, 보이스·립싱크 작업은 `22-dialogue-lipsync.md`, 실제 도구 용량은 `24-production-execution.md`를 따른다.
