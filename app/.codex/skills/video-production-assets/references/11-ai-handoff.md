# AI 영상 프롬프트·연속성 인계

## 입력과 산출물
입력: 확정 샷, 캐릭터·룩 SSOT, 생성 도구 기능

산출물: 샷별 프롬프트, 참조 매핑, 재생성 로그

## 실행 절차
1. 실제 도구의 참조 이미지·클립 길이·화면비·오디오·카메라 제어 지원을 확인한다. 지원하지 않는 파라미터를 발명하지 않는다.
2. character_id·location_id·prop_id·look_id에 승인된 기준 에셋을 연결한다. seed만으로 인물 일관성을 보장하지 않는다.
3. 샷 프롬프트를 대상/환경→초기 상태→하나의 주 행동→카메라→조명→끝 상태→유지 규칙 순서로 쓴다. 복합 변신·과도한 사건은 샷을 나눈다.
4. 앞 샷 끝과 다음 샷 시작의 의상·소품 손·시선·진행 방향·광원을 맞춘다. 생성 클립 길이와 최종 편집 길이·핸들을 구분한다.
5. 검수 후 문제 위치를 시간으로 기록하고 한 변수씩 수정한다. 실제 생성 전에는 프롬프트 완성으로만 보고하고 영상 완성이라고 말하지 않는다.
6. 플랫폼별 생성·편집·게시 작업은 해당 도구/스킬의 권한과 절차로 인계한다. 이 모듈 자체가 렌더링이나 외부 게시를 실행했다고 주장하지 않는다.

## 상태·인과 연속성 (선택적)
샷이 누적 변화·원인 동작·시점 대응·결합 응답·시간 압축·정확한 레퍼런스 중 하나에 해당하거나 앞선 샷의 후속 유지 의무를 이어받으면 [상태·인과·연속성 인계](26-state-causality-continuity.md)의 필요한 슬롯을 기존 산출물 또는 `assets/state-transition-template.md`에 채워 다음 해당 샷/검수로 넘긴다. 시작·끝 상태·유지 규칙 위에 변화 영역/속성·보존 영역/속성·후속 유지 범위·의도적 생략을 분리한다. 새 변화와 상속된 유지 의무가 모두 없는 샷에만 `상태 인계: N/A`로 닫고 필드를 강제하지 않는다.

## 완료 조건
주 행동이 명확하고 가능한가? SSOT 참조가 있는가? 시작·끝 상태와 샷 간 연속성이 맞는가?

## 근거와 적용 범위
자료 ID: 설계 확장; 05,08,13,16,33의 제작 원칙 응용. `sources.md`에서 파일 상태와 탐색 위치를 확인한다. 절차와 템플릿은 여러 자료의 개념을 결합한 독자 설계다. 저자의 규칙을 그대로 재현한 요약이나 공식 인증된 방법론으로 표현하지 않는다.
