# 모션·합성·생성 영상 QA·인과 재시도 (온디맨드 심화)

모듈 11(AI 인계)과 12(제작 검수)의 심화. 실제 생성/합성 매체가 있거나 복잡한 동작·접촉·VFX를 계획할 때 연다. 계획 단계에서는 설계 절차만 적용하고 실제 매체 없이 검수 통과를 주장하지 않는다.

## 1. AI 모션·물리 디렉팅

복잡한 동작을 통제 가능한 물리 비트로 나눈다. 걷기·달리기·무술·춤·잡기·붓기·제품 접촉·운반·충격·점프·동물의 물리 행동·천/머리카락·액체처럼 접촉·균형·무게·충돌·타이밍·동시 다발 행동 때문에 실패하기 쉬운 샷에 적용한다.

1. 초기 포즈·지지점·무게중심·접촉 사물·최종 포즈를 정한다.
2. 샷을 하나의 주 행동으로 표현한다. 독립 행동이 여럿이거나 변형이 끼면 샷이나 순차 생성 구간으로 나눈다.
3. 해당하면 예비 → 시작 → 이동 → 접촉/충격 → 체중 이동 → 후속 → 정착으로 쪼갠다.
4. 붙어 있어야 할 것을 명시한다: 발·발바닥·손·좌석·도구·제품·바닥·벽·상대.
5. 동사가 아니라 궤적과 상대 운동을 기술한다: 방향·속도 변화·호·정지 조건.
6. 접촉 순간의 해부·사물 무결성을 지킨다. 장식적 2차 동작보다 믿을 수 있는 접촉을 우선한다.
7. 2차 동작은 주 행동이 읽힌 뒤에만 추가한다: 머리카락·천·귀·꼬리·느슨한 사물·튐·먼지.
8. 액체·군중·파괴·복잡 충돌은 한 번의 생성에 요구하지 말고 합성으로 라우팅한다.

### 접촉 우선순위

지지와 중력 → 주 접촉 → 사물 무결성 → 신체 역학 → 2차 동작 → 장식 파티클. 낮은 우선순위 동작이 높은 항목을 해치면 제거한다.

### 샷 분할 트리거

중요한 접촉이 3개 이상 · 변형+이동 동시 · 여러 인물의 사물 교환 · 큰 카메라 무빙+복잡 동작 · 정밀 제품 다루기+액체 시뮬레이션.

### QA와 산출물

발 미끄러짐·떠 있는 사물·관통·불가능한 균형·손 변형·텔레포트 소품·비일관 관성·이른 동작 리셋을 검수한다. `assets/motion-beat-template.md`로 비트 시트를 만든다.

## 2. VFX·합성 수퍼비전

어려운 샷을 한 번의 생성에 억지로 넣지 않는다. 레이어 구성이 더 통제 가능할 때 분해한다.

1. 샷을 단일 플레이트로 생성할지 레이어로 분해할지 정한다.
2. 레이어 스택을 정한다: 배경 · 중경 · 히어로 피사체 · 제품/소품 · 그림자 · 반사 · 대기 · 파티클 · 타이포/UI · 전경 가림. `assets/vfx-layer-stack-template.md` 사용.
3. 색보다 카메라 형상을 먼저 맞춘다: 지평선·원근·스케일·렌즈 느낌·심도·모션.
4. 조명을 맞춘다: 키 방향·부드러움·강도 관계·색온도·림·바운스·접촉 그림자·반사광.
5. 가림·대기 깊이·모션 블러·디포커스·그레인/노이즈·정당할 때만 라이트 랩으로 가장자리를 통합한다.
6. 반사와 그림자는 실제 표면과 움직임을 따른다. 일반적인 뜬 드롭 섀도를 피한다.
7. 텍스트·로고·정확한 패키지는 생성 충실도가 부족하면 통제된 그래픽/제품 레이어로 유지한다.

### 매칭 순서와 경고 신호

형상 → 모션 → 조명 → 접촉 → 깊이 → 색 → 질감/그레인 → 광택. 경고: 떠 있는 피사체·흐린 플레이트 위 선명한 전경·불일치 셔터/모션 블러·다른 그레인 주파수·어울리지 않는 블랙 레벨·잘못된 광원 측·그림자 방향 불일치·틀린 환경 반사·안개 낀 장면의 완벽한 컷아웃 가장자리.

전체 프레임과 클로즈 줌 둘로 검수한다: 가장자리 헤일로·불일치 블랙·불일치 그레인·틀린 블러·뜬 발·빠진 접촉 그림자·원근 불일치·불가능한 반사.

## 3. 생성 매체 QA

실제 매체를 판정하고 프롬프트를 판정하지 않는다. 파일이나 필요한 프레임/오디오가 없으면 해당 항목을 unverified로 남긴다.

### 검사 순서

실제 매체를 이 순서로 본다 — 부합(요청한 대상/행동/의도가 실제로 나왔는가) → 모션(접촉·균형·시간 안정) → 정체성(SSOT·제품 정확도) → 카메라(프레이밍·방향·공간) → 오디오(입·목소리·소리 원근) → 기술 규격(길이·화면비·해상도·프레임 무결성·필요 시 오디오 존재). 앞 단계의 blocker가 보이면 뒤 패스의 세부 미학 판정으로 넘어가지 않는다.

### 검사 패스 (여러 모드로 본다)

1. 정속 시청(소리 포함) 2. 정속 무음 3. 의심 구간 슬로/스텝 4. 시작·핵심 접촉·끝의 정지 프레임 비교 5. 샷 간 연속성 비교 6. 대사/소리가 중요하면 오디오만 듣기.

- 정체성 패스: 승인 SSOT와 인접 샷에 대해 얼굴/몸/머리/털/의상/액세서리 비교.
- 사물/제품 패스: 실루엣·비율·캡/부품·라벨·로고·스케일·손 접촉·반사·텍스트 가독성.
- 모션 패스: 발과 손부터 본다. 예비·접촉·체중 이동·후속·충돌·미끄러짐·튐·해부 초과/결손·사물 영속성.
- 시간 패스: 플리커·모핑·질감 기어감·불안정 그림자·사라지는 디테일·배경 호흡·서사와 무관한 조명 변화.
- 카메라/공간 패스: 지평선·렌즈 느낌·원근·프레이밍·시선·화면 방향·동기 있는 움직임·편집이 요구한 시작/끝 상태.
- 합성 패스: 가장자리·깊이 순서·접촉 그림자·광원 방향·그레인/노이즈·모션 블러·심도·블랙/화이트 레벨·대기 통합·반사 논리.
- 연기/오디오 패스: 시선·표정 전환·반응 타이밍·대사 의도·입 타이밍·숨·멈춤·노이즈·클리핑·소리 원근과 화면 일치.

### 판정

이슈마다 `타임코드 → 관찰 → 관객 영향 → 심각도 → 추정 원인 → 권장 경로 → 재검수 기준`으로 기록한다. 심각도와 판정은 모듈 12의 blocker/major/minor와 pass/pass_with_notes/needs_revision을 사용한다. 생성 결함은 아래 재시도 절차로, 창작/서사 실패는 상위 모듈로, 정확한 그래픽과 레이어 통합은 합성 절차로 되돌린다. `assets/generated-qa-report-template.md` 사용.

실제 매체를 검사하지 않고 가상의 품질 점수를 매기지 않는다. 사용자 제공 루브릭과 실제 검사가 있을 때만 점수를 쓴다.

### 프리뷰 판정과 최종 검수

실제 출력만 판정한다: 짧은 프리뷰는 뒤 구간의 동작·접촉·연속성을 증명하지 않으므로 보이지 않은 대상을 통과로 쓰지 않는다. 수락/수정/경로 변경은 [생성 경로·비용 라우팅](24-production-execution.md) §5의 프리뷰 계획 대상과 승격 경로로 되돌린다. 프리뷰 수락은 최종 승인이 아니며, 최종본의 동작·정체성·오디오·기술 규격은 다시 검수한다 — 같은 seed·입력의 재생성은 같은 동작을 보장하지 않는다.

### 상태·인과 검수 (선택적)

직접 또는 앞선 샷에서 이어받은 [상태·인과 슬롯](26-state-causality-continuity.md)이 있는 샷에 적용한다. 판정 enum과 실패 분류는 그대로이며, 여기서는 근거 위치와 미검증 구분만 추가한다.

- **구간 검사**: 시작·끝 프레임이 달라 보이는 것만으로 원인 동작이 성립했다고 판정하지 않는다. 접촉/변화가 진행되는 구간을 실제로 본다. 구간을 보지 못했으면 전이를 unverified로 남긴다.
- **후속 경계**: 선언한 유지 범위 안의 모든 해당 후속 컷 경계·재등장 상태를 문서화된 리셋까지 대조한다. 중간 정지 컷·가림도 의무를 지우지 않으며 의도적 리셋과 상태 리셋 오류를 구분한다.
- **가림**: 가려진 동안 안 보인 특징을 상태 역전·삭제로 판정하지 않는다. 가림 전 관측과 재등장 관측을 비교하고, 재등장이 없으면 미확인으로 둔다.
- **결합 응답**: 인계된 대상쌍이 있으면 양쪽의 응답을 각각 본다. 응답 구간을 검사할 수 없으면 unverified로 남기고, 검사했는데 요구된 응답이 실제로 빠져 있으면 모션/물리 실패로 분류해 needs_revision으로 되돌린다.
- **생략**: 승인된 서사 생략은 전후 상태와 관객이 읽는 인과가 브리프를 충족할 때만 허용한다. 생략 표기만으로 필수 시연을 면제하거나 보이지 않은 동작을 증명하지 않는다. 생략된 동작 자체는 unverified로 남기고, 관찰된 필수 행동 누락은 needs_revision으로 되돌린다. 경계·인과 누락을 빠른 컷이나 음악으로 감추지 않는다.
- 새 활성 조건과 상속된 유지 의무가 모두 없는 `N/A` 샷에만 이 패스를 적용하지 않는다.

### 실행·상태 수명 주기

선택 실행자의 실제 호출 계약(API·CLI·연결 도구 중 실제 것)으로만 승인된 범위를 제출한다. 비동기 작업은 그 도구의 대기/폴링 규칙을 따르고 실제 요청·작업·결과 ID와 대기 상태를 연결된 실행 산출물에 기록한다. 상태가 불명이면 먼저 그 도구의 상태 확인으로 결정하고, 실패·부분 성공을 그대로 보고한다 — 제출 성공 여부를 확인할 수 없을 때 다시 호출해 중복 실행·과금을 만들지 않는다. 실제 결과 파일을 받아 검사한 뒤에만 성공으로 기록한다. 자신의 검사와 사용자의 관찰 보고를 구분하고, 수정은 성공 속성을 보존한 채 한 번에 한 주요 변수만 바꿔 §5에 기록한다. 과거 시도 기록은 보존하며 입력 버전 변경 시 영향받는 종속 산출물·승인만 stale로 표시한다; 시도에 별도 stale 상태를 만들지 않는다.

## 4. 완성 시퀀스의 모션·리듬·오디오 QA

클립별 생성 QA를 통과한 것만으로 광고/몽타주의 역동성이나 편집 싱크를 승인하지 않는다. 완성 타임라인에서 확인한다.

1. 편집본·오디오·타임라인의 artifact ID와 버전을 고정한다. 검사 범위(전체 재생, 표본 프레임, 오디오 단독)를 각각 기록한다.
2. 역동성 요청이면 샷마다 실제 피사체 동작, 카메라 동작, 제품/정보 공개, 정지/정착 중 무엇이 시간에 따라 바뀌는지 적는다. 컷 속도나 디졸브만으로 모션을 대체했다고 판단하지 않는다.
3. 실제 편집본을 정상 속도와 최종 믹스로 재생해 전체 페이싱·전환을 확인한다. 중요한 접촉·충격·제품 공개는 프레임/타임코드와 오디오 동기 기준점을 대조한다. 무음·오디오 단독 검수는 요청과 문제 유형에 맞게 추가한다.
4. 샘플 프레임만 검사했으면 모션의 중간 프레임, 전환의 실제 길이, 전체 음악 적합성은 미검증으로 둔다. 청취하지 않은 음원의 품질이나 싱크를 통과로 쓰지 않는다.
5. 오디오가 참조 영상의 단일 혼합 트랙이면 분리 BGM/SFX stem이 없음을 기록한다. 분석 도구가 찾은 파형 피크는 청취 판정이 아니며, 음원 권리는 별도 확인한다.
6. 정지/거의 정지된 원본은 요청된 비트가 실제 움직임을 요구하는지 먼저 판단한다. 의도된 제품 히어로 홀드로서 화면 내용·가독성·타이밍이 이를 뒷받침할 때만 보존한다. 정지 상태라는 이유만으로 보조 컷이나 엔드카드 역할을 추정하지 않는다. 동작이 필요한 비트가 성립하지 않으면 더 강한 실제 동작 구간을 선택하거나 샷 교체안을 낸다. 확대/전환 효과만으로 움직임을 꾸며내지 않는다. 새 생성·유료 실행은 별도 승인과 기존 비용/재시도 상한을 따른다.

보고에는 타임라인 범위·실제 검사 모드·도구/파일·관찰된 타임코드·미검증 항목·재검수 기준을 포함한다. `assets/generated-qa-report-template.md`를 사용한다.

## 5. 인과 재시도 제어

실패한 생성은 진단 문제다. 매번 전부 다시 쓰지 말고 가장 이른 통제 가능 원인을 고친다.

### 실패 분류

- 정체성: 얼굴 표류·신체 비율 변화·의상/액세서리 표류·종/연령 변화.
- 제품/그래픽: 형태 표류·캡/라벨 변화·로고/텍스트 손상·재질 불일치·틀린 스케일.
- 모션/물리: 초과 사지·발 미끄러짐·깨진 접촉·텔레포트·불가능한 균형·사물 관통·이상한 유체.
- 시간: 플리커·모핑·질감 기어감·사라지는 사물·불안정 배경·불연속 조명.
- 카메라/구도: 틀린 프레이밍·의도 없는 줌/팬·피사체 이탈·지평선/원근 불일치·시선/화면 방향 단절.
- 연기: 틀린 감정·늦은 반응·입 불일치·죽은 눈·의도와 다른 제스처.
- 합성: 나쁜 가장자리·빠진 접촉 그림자·틀린 깊이·불일치 블러/노이즈/색·스케일/원근 불일치.
- 창작: 불명확 아이디어·약한 보상·중복 샷·낮은 감정 가치. 맹목적 재생성 대신 상위로 보낸다.

### 실패 → 수정 매핑

| 관찰된 실패 | 첫 수정 | 상승 경로 |
|---|---|---|
| 부합 불일치(요청한 대상/행동이 아님) | 프롬프트를 요청 의도·주 행동·끝 상태로 다듬기 | 샷 분할 → 모델 재라우팅 |
| 모핑/시간 불안정·플리커 | 구간 단축·행동 단순화·참조 강화 | 세그먼트 분할 → 합성 |
| 정확한 텍스트/로고 손상 | 반복 생성 중단, 승인 아트워크 합성 레이어 | 합성 경로 확정 |
| 물리/접촉 붕괴 | 동시 행동 축소·접촉 분해·초기/끝 상태 명시 | 샷 분할 → 레이어 합성 |
| 정체성 표류 | 승인 SSOT 참조 강화·상충 지시 제거 | 더 강한 참조 제어 경로 → 재라우팅 |
| 카메라 불일치 | 지원 확인된 구조화 카메라 제어만 사용 | 카메라 제어 지원 경로 → 프레임 합성 |
| 오디오/립싱크 불량·미지원 | 미지원 시 생성 경로 변경 | 별도 음성/립싱크 패스로 분리 |
| 프롬프트 과부하 | 다듬기: 한 샷 한 주 행동·유지 규칙만 | 샷 분할 |
| 창작 실패(지루함·약한 보상) | 재시도 아님 — 상위 콘셉트/편집으로 송부 | — |

### 절차

1. 의도한 샷 명세·선택된 모델 경로·승인 SSOT·실제 출력을 받는다.
2. 위 QA로 관찰 가능한 실패를 분류한다.
3. 원인을 판정한다: 프롬프트 모호 · 약한 참조 제어 · 과도한 행동 복잡성 · 모델 능력 불일치 · 나쁜 초기 프레임 · 연속성 의존 · 합성 필요 · 확률적 분산.
4. 고칠 가능성이 큰 가장 작은 개입을 고른다. 실용적으로 한 번에 한 주요 변수만 바꾼다.
5. 재시도 시 성공한 속성을 명시적으로 보존한다.
6. 반복 실패 시 무차별 재시도 대신 상승한다: 행동 단순화 → 샷 분할 → 레이어 분리 → 모델/워크플로 변경 → 더 나은 참조 에셋 → 정확한 요소 합성 → 서사 목적을 유지한 샷 재설계.
7. 재시도 예산을 지킨다. 다음 생성의 기대 가치가 전략 전환보다 낮으면 멈춘다.
8. 성공 설정이 재사용되도록 매 시도를 `project.json`의 `generation_attempts`에 기록한다(계약 v1.1). 샷 `retry_budget`은 승인된 `video_execution_plan`의 상한에서 온다.

### 재시도 사다리

프롬프트 명료화 → 참조/첫 프레임 교정 → 행동 단순화 → 길이/타이밍 조정 → 샷 분할 → 모델/워크플로 재라우팅 → 레이어 분리/합성 → 서사 목적 유지 샷 재설계.

### 규칙

- 한 번에 한 변수: 재시도마다 하나의 주요 변수만 바꾸고 변경 내용을 generation_attempts.changes에 남긴다. seed는 재현 힌트일 뿐 정체성·품질 보장 수단이 아니며, seed만 고정한 재시도를 원인 수정으로 세지 않는다.
- 경계 있는 재시도: 샷 retry_budget과 승인된 실행 계획의 비용·시간 상한 안에서만 시도한다. 상한 초과 전에 전략 전환(분할/재라우팅/합성) 또는 unverified 보고로 닫는다.
- 관객이 인지하는 연속성 실패를 빠른 편집으로 숨기지 않는다.
- 정체성 표류를 수십 개 형용사로 고치지 않는다: 정규 참조를 강화하고 상충 지시를 줄인다.
- 정확한 텍스트/로고는 반복 생성보다 합성을 우선한다.
- 접촉 중심 물리는 동시 행동을 줄이고 초기/접촉/끝 상태를 정의한다.
- 생성 실패와 창작 실패를 구분한다. 완벽히 렌더링된 지루한 샷은 재시도가 아니라 콘셉트/편집으로 돌아간다.
