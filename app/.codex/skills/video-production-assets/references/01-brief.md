# 영상 브리프·제작 설계

## 입력과 산출물
입력: 아이디어, 대상 관객, 플랫폼, 영상 길이, 예산·인력·도구

산출물: project.json, 제작 브리프, 범위·가정 목록

## 실행 절차
1. 관객이 처한 상황과 영상 후 바뀔 인식·감정·행동을 각각 한 문장으로 정한다. 브랜드 목표와 주인공 목표를 구분한다.
2. 실사 / 애니메이션 / AI 생성 / 혼합 중 제작 방식을 정한다. 길이·화면비·fps·언어·게시 위치를 공통 계약에 기록한다.
3. 핵심 약속을 보여줄 증거 장면을 선택한다. 광고는 주장→증거→행동, 설명 영상은 질문→관찰→해석, 드라마는 욕망→장애→선택을 출발점으로 삼는다.
4. 필수 샷과 선택 샷, 촬영 자원과 의존성을 정한다. 사용할 수 없는 장소·인원·도구는 대체안으로 해결한다.
5. 정보가 부족하면 실행에 필요한 가정을 표시하고 초안을 진행한다. 실제 인물·상품·수치를 지어내지 않는다.

## 프로젝트별 스타일 브리프
레퍼런스 기반 작업이나 여러 샷·단계의 일관성이 필요한 경우 기존 브리프/비주얼 바이블 안에 필요한 스타일 항목만 둔다. 단일 원고·프롬프트에 별도 스타일 문서를 강제하지 않는다.

- **공용 제작 원리**: 정보 공개·스케일 변화·컷과 동작의 관계처럼 다른 소재로 이전할 수 있는 규칙. [레퍼런스 분석](25-reference-video-analysis.md)의 근거·해석·적용 요구를 연결한다.
- **프로젝트 고유 룩**: 팔레트·조명·질감·카메라·편집·사운드·금지 요소 가운데 필요한 항목만 정한다. 각 값은 사용자 제공/승인, 제안, 미정으로 구분하고 실제 근거가 없는 브랜드 룩을 만들지 않는다. 레퍼런스의 색이나 소품이 승인된 채널 룩을 덮어쓰지 않는다.
- **범위와 버전**: 해당 프로젝트에서 선택한 스타일 버전과 출처/검사 구간을 인계한다. 다단계 제작은 기존 artifacts/의존 버전으로 브리프를 연결한다. 다른 프로젝트의 프로필은 명시적으로 제공·선택된 버전만 사용하며 전역 프로필이나 설치된 스킬에 사용자 데이터를 저장하지 않는다.
- **검수 요구**: 스타일 항목마다 화면·타이밍·청취로 확인할 수 있는 기준을 붙이고 샷/패널/프롬프트 담당에게 전달한다. 근거 위치 → 제작 원리 → 새 소재의 요구 → 정성 검사 기준의 연결은 레퍼런스 분석 표를 재사용한다. 실제 ID는 산출물이 생긴 단계에서 연결하며 제안 시간을 측정 시간처럼 표시하지 않는다.

스타일 변경은 영향을 받는 검토/실행 계획의 기존 stale·재승인 규칙을 따른다. 브리프 수락은 생성·추가 재시도·게시 승인이 아니다.
