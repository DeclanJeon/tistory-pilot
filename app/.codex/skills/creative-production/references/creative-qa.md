# Deliverable verification

Apply only the requested output's checks. Record actual evidence and unverified conditions separately. Draft, generated file, inspection, user acceptance and publication are different states; a validator/model judgment is not user approval or legal clearance.

## Text and planning

- Show the requested artifact in the requested language/format, not merely a completion report.
- Trace factual claims to supplied/verified sources; separate arithmetic, interpretation, fiction and proposals. Unknown causes and outcomes stay unknown.
- Preserve fixed facts, characters/products, continuity, approved direction and exclusions across requested stages.
- Check specified timing allocations sum to the requested duration without presenting estimates as frame-accurate execution.
- Apply narrative/commercial structure only when it fits the brief. Omit inapplicable characters, CTA, extra formats and unrequested stages.
- Saving requested text does not imply images, video, project state or publication.

## Actual audio/video

- Confirm the real files and canonical IDs/versions; distinguish failed or missing outputs from successful ones.
- Listen to audio for script fidelity, pronunciation, noise, pacing and sync.
- Inspect actual video frames and transitions for temporal artifacts, subject/product continuity, camera action, unwanted objects and intended composition.
- Probe duration, frame rate, aspect/resolution, encoding, captions and audio sync with available media tools.
- Compose critical words, logos, prices and legal text deterministically when needed; check actual readability.
- Check the requested delivery format and destination-specific conditions. A preview/API success is not a final encode.
- When reference intent or project style is a requested criterion, use [production QA](../../video-production-assets/references/12-qa.md#레퍼런스-의도-대조-해당-작업만) for evidence-backed qualitative comparison and requested retrospectives.

## Blender/3D and web

- Open/render the actual Blender scene when that is the output. Check intended camera, scale, blocking and geometry against the source specification.
- Inspect scripts before execution and preserve unrelated files/scene objects. A mathematical projection or proxy is not photoreal/final-media QA.
- Load actual exported assets in the requested surface; check materials, memory/geometry budgets, interactions and relevant fallbacks.
- For actual web deliverables, inspect the rendered browser route, accessibility, keyboard/focus, mobile/loading/error/reduced-motion behavior and applicable performance measures. Source inspection alone is insufficient.

## Provenance, authorization and delivery

- Record relevant source/asset/provider/model versions and actual file paths. Check selected-provider terms/rights live when required; don't claim general commercial/legal safety.
- Verify execution was within its version-bound scope and spend/retry/time caps. Changed inputs make affected approvals stale, not all project approvals.
- Keep secrets and private user sources out of published artifacts.
- Report actual exercised verification and remaining limitations. No publication or live changes from a draft-only request.
